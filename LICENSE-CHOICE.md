# License Selection — ACTION REQUIRED

**This repository deliberately does not include a LICENSE file.**

A public GitHub repository is not automatically granted an open-source license. Before publishing product code, the responsible owner must select and add a complete license text with the correct copyright attribution.

## Common code licensing options

- **MIT:** permissive, short notice/attribution obligation.
- **Apache-2.0:** permissive with an explicit patent license and additional conditions.
- **GPL-3.0-or-later:** reciprocal copyleft, with conditions for distributed derivatives.
- **MPL-2.0:** file-level copyleft, often used for libraries and tools.

These are examples, not legal advice. Match the license to dependencies, distribution method, contributor intent, and organizational approval. Do not copy a random license header or use a placeholder as though it were a valid license.

## Brand assets are separate

The organization's logos, calligraphic seals, banners and typography are **not automatically licensed** under any source-code license. Obtain explicit permission and review the relevant brand policy.

Once a decision is made:
1. Add LICENSE at the repository root.
2. State the chosen license in both language READMEs.
3. Review any third-party assets and dependency notices.
4. Update this document or remove it after the decision is final.
